The terminal · mockup

A pathfinder for the terminal client and the commands, in the look of the web client's mockup. Nothing here is built.

Every frame is a terminal drawn cell by cell, and it is live: click one and use the keys the client has. Press Ctrl+G in any of them for the list. Off a Mac, the browser keeps Ctrl+N and Ctrl+T for itself.

01One level at a time

At 80 columns the client has the levels it has today: agents and rooms, then what one agent takes part in, then a thread. It takes the whole screen, and the last line is the keys.

A thread, and the same thread turned over with Tab to the session as the agent sees it. The input stays under both.

02Side by side

A wider terminal shows the levels beside each other: two from 96 columns, three from 128. The keys don't change. Enter goes in, Esc goes out, and the bar marks the list the keys are in.

03A busy room

Each agent at work gets its name and its latest step, and Ctrl+O opens them all. Under them the dock keeps to a line for each kind of thing: who is working, and the soonest wake-up with a count. /status lists every wake-up and says once what /stop does to them.

04Finding a key

A key that acts on one thing is named beside that thing. The last line names the keys that move you, and Ctrl+G lists every key. A slash opens the commands, as it does now.

05When things are not fine

A view with no connection goes dim under its note, a thread you only read says so where the input would be, and with no gateway the first screen is how to start one. The notes about a lost connection and a missing gateway are the terminal's sentences as they are today. The others are the shorter ones from the web mockup.

06On the terminal's own colors

Where a terminal has no true color, the client paints no ground: it draws on the terminal's own, in its sixteen colors. The layout and the marks are the same.

07The commands

The commands print plain lines and tables, which agents read, and those stay as they are. On a terminal that shows color, three things are added: a name or a command to run is bold, a state has a color, and what failed is red.

08What it is made of

The web client's stitch is two pixels. Here it is the cell, and the dot of a braille cell: the wordmark and each sigil are their same bitmaps, drawn in dots.

The same colors, by name

The tokens are the web mockup's. A word uses the form that is safe for small text, and a mark uses the brighter one.

    09What this changes, and what it leaves open

    None of this is in the plan yet. The first card is where it differs from the terminal as it is built and as the plan has it, each one for you to take or strike.

    Changed here

    1. The whole screen. Today the client draws into the terminal's scrollback. Here it takes the alternate screen, so lists can stay on show and the input stays at the bottom. The plan has this as later, since the first spike lost the transcript on the way out. The pi-tui that Shrimpy has now, 1.0.0, says it prints the whole thread back when the client leaves. That is from its README, and not tried.
    2. Scrolling is the client's. PgUp, PgDn and the wheel scroll the pane they are in, a drag selects and copies, and Ctrl+Shift+F searches. All three are pi-tui's. The plan left scrolling keys for later because the scrollback had them.
    3. The levels sit side by side where there is room, and Ctrl+\ puts them back to one at a time. The web client folds its lists on the same key.
    4. Where a key is named. The plan's fourth rule has every key on the last line, and you called that line crowded. Here a key is named beside what it acts on, the last line has the keys that move, and Ctrl+G lists them all.
    5. Tab turns the thread over and the input stays, so you can write while you watch the agent's view. In a room, Tab goes through each agent's view and back to the conversation.
    6. Each agent has a pigment, as on the web, and a sigil where there is room for one. Today every agent is one color.
    7. What is new to you is counted by each agent and thread, as the web mockup has it. Seeing what arrived while the terminal was closed is on your list as later, and soon.
    8. The dock is a line for each kind of thing: who is working, what is queued, and the soonest wake-up with a count, whichever agent's it is. /status lists them all, in a room too. The shrimp still walks while an agent works.
    9. The tab's title has the shrimp, which you asked for, and with it how many agents are working and how much is new.
    10. The mouse works, for choosing a row and for the wheel. Nothing needs it.

    Not drawn yet

    • Signing in from the terminal, and /thinking.

    Yours to choose

    • The ground. Painted, as in most frames here, or always the terminal's own, as on sheet 06.
    • The two new keys. Ctrl+G for the list of keys and Ctrl+\ for the fold are my picks, and easy to change.
    • Sigils in a terminal. Braille dots depend on the font, and the client can't ask a terminal which font it has. The client is whole without them.
