web client · mockup · the reference for its look since 2026-11-21

One frontend, laid out for the width it has: a level at a time on a phone, side by side at a desk. Every frame on this page is the same code at a different width, and each one is live. Click around in them, and send a message in any thread to watch a scripted turn.

Nothing here talks to a gateway. What decides the look is one block at the top of this file: two wools, eight pigments, two faces and a stitch.

01At a desk

Agents and rooms, then everything one agent takes part in, then a thread. The lantern by an agent is lit while it works, in the list and on the tide above it.

Folded, the two lists are a strip of sigils, with each lantern and new mark still on it. The pointer brings the lists back over the thread until it leaves them.

02On a phone

The same three levels, one at a time, with no browser bar around them.

03The other time of day

The two wools trade places: the ground of one is the ink of the other. Here the agent's view is open, which puts the session as the agent sees it beside the conversation. On a phone the same button turns the thread over.

04When a room is busy

However many agents are at work in a thread, one of them is open and the others take a line each. However many triggers come to it, the dock shows the soonest and a count, and the rest open in place.

05What is still going

An agent that ends its turn can leave things going: a command in the background, a question to another agent, a trigger. The thread keeps them in one block above the input, a row for each kind, and a row opens in place. Here the coding agent scout started has been building for twelve minutes, and scout's lantern stays lit for as long as it does. Its last output is a click away, and so is ending it.

Asking another agent starts a thread with it, and the thread you asked in waits for the answer. A name in that row opens the thread with that agent, under observe, where its work shows as it happens and a button stops its turn. That thread says who waits on it and from where, for as long as the wait is open. The answer leaves a line where you asked, which opens the thread it came in.

Whatever wakes an agent with no message of anyone's leaves a line: a trigger that fired, a command that ended, an agent that answered. A line opens to what it brought. A thread that a trigger comes to can hold little else, since an agent with nothing to report writes nothing.

The agent's view shows the same turns from inside: the question it posted, what it was shown when the answer came, and the thread it archived once it had it.

An agent is working while anything of its runs, a turn or a command it left in the background, and one lantern says both. An agent that only waits on another says so in words, and is idle only when it waits on no one. The row of the agents waited on opens to each wait, with a way to stop waiting that is kept apart from the names: that is how a person ends a wait on an agent that isn't running. A trigger that comes to a thread has its row there too: a one-time trigger with cancel, and a standing one with pause.

06An agent's page

While no thread is open, an agent's page stands where the thread would: how the agent stands, where it runs, its triggers and its home. Every trigger is there: a standing one as its file, with the thread it comes to, a switch and a way to run it now, and the one-time ones under them. The list beside it holds only conversations, in two tabs: chat is your DM with the agent, and observe is everything else it takes part in.

On a phone the page opens from the agent's name or sigil at the top of its list. A file in the home opens where the page was, and back goes to the page.

While a command of the agent's runs in the background, the page lists it above the triggers, with the thread that started it, its last output and a way to end it.

In observe a thread says where it is: a room, or a DM with another agent. Every row is a thread. A thread opens its agent's list on the tab that holds it.

An agent that is off still says where it lives. One the gateway turned away for its release says what to update.

07When things are not fine

A view with no connection loses its color and says so. A thread you only read says why there is no input. A slash opens the commands, and /status answers above the input, for you alone.

08Renaming and archiving a thread

A thread you can write in has a menu with both. /rename and /archive written in the thread do the same.

Renaming turns the name into an input where it stands.

An archived thread leaves its list for the group at the foot of it. It comes back from the same menu, or when a message lands in it.

09Pictures and files

The paperclip by the input opens the phone's own picker. What is picked waits in the input until it is sent, and its cross takes it off. In the thread a picture shows itself, and a file is its name and its size.

At a desk a pasted picture, or a file dropped on the thread, joins the input the same way. A file too big to send is left out, and a note says so.

The agent's view shows the picture the model was shown with the message, and where the file was put in the agent's home.

A tap opens a picture whole. A model that takes no pictures is shown Pi's line in place of one, so the agent knows to say it can't see it.

10What it is made of

The studio's guardrails, applied to a surface that is read for hours: a warm dark that is never black, pigment that sits close to the ground, and pixels used as a quiet material.

Dusk navy heather

The ribbing of the sweater in the studio's refs: dark navy with warm flecks. Cream is the ink.

Day cream wool

The body of the same sweater. Navy is the ink, and the flecks turn to the blue of its clouds.

Pigments at dusk

Faded and matte, and each one means something. Most of a screen is ground and ink.

Pigments by day

The same pigments, deepened for paper. Each has a darker form for small text.

One stitch 2px

Every texture is drawn on one grid, the size of a stitch. Nothing glows and nothing blurs: where a value has to fade, it is dithered.

Marks

The terminal's marks, drawn on the stitch. A mark never stands without its word where the word matters: a failure says failed.

Sigils 12 × 12, one color

An agent's face is a bitmap small enough to keep as twelve lines of text. It holds at 12px beside a name, and as a relief on an empty screen.

Type Atkinson Hyperlegible

You chose it over the system's own face on 2026-11-22: "that one". It was drawn for readers with low vision, so its letters are hard to mistake for each other, and it is the same on every device. The web client serves its files itself. This page fetches them from Google, and falls back to the system's own face with no network.

Atkinson Hyperlegible Next

For what a person or an agent wrote.

0O 1lI 5S rn m

Atkinson Hyperlegible Mono

For what a machine wrote: tool calls, paths, times, commands and the line of keys.

restic snapshots --latest 1 · 0O 1lI 5S rn m

No bitmap type: pixels are the material, and words stay crisp beside them.

Steps

Everything that moves, moves in steps. The tide is redrawn twice a second, the halo of a lantern has three frames, and the shrimp walks at the terminal's 180 ms. Reduced motion stops all of it.

At other sizes

The same marks in the terminal as it is today, on a small matte screen, and in a browser tab.
