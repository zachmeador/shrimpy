# 🦐 Ralph Loop Reference

Date: --
Status: Research

A synthesis of the Ralph Wiggum technique for autonomous AI agent loops, drawn from Geoffrey Huntley's original work, Ryan Carson's snarktank/ralph implementation, the Anthropic claude-code plugin, and the ClaytonFarr/ralph-playbook.

---

## Core Concept

Ralph is a bash loop that repeatedly spawns fresh AI agent instances against a structured task list until all tasks pass. Each iteration gets clean context. Memory persists only through files on disk: the PRD (task list), a progress log, git history, and an operational guide.

The agent reads the task list, picks the next incomplete item, implements it, runs tests, commits, updates the task list, and exits. The loop restarts with a fresh context window.

```bash
while :; do cat PROMPT.md | claude -p --dangerously-skip-permissions; done
```

That's it. Everything else is context engineering around this core.

---

## Architecture: 3 Phases, 2 Prompts, 1 Loop

### Phase 1: Define Requirements (human + LLM conversation)

- Identify Jobs to Be Done (JTBD)
- Break each JTBD into topics of concern
- Write one spec per topic → `specs/FILENAME.md`
- No implementation, just requirements

### Phase 2: Planning (loop with PLANNING prompt)

- Agent reads all specs + existing source code
- Performs gap analysis (what exists vs what's specified)
- Produces prioritized task list → `IMPLEMENTATION_PLAN.md`
- No implementation, no commits
- Usually completes in 1-2 iterations

### Phase 3: Building (loop with BUILDING prompt)

Per iteration:
1. **Orient** — read specs, plan, operational guide
2. **Select** — pick highest priority incomplete task
3. **Investigate** — search codebase before assuming anything is missing
4. **Implement** — make changes for one task only
5. **Validate** — run tests/typecheck/lint (backpressure)
6. **Update plan** — mark task done, note discoveries
7. **Update operational guide** — if reusable learnings found
8. **Commit** — only if checks pass
9. **Exit** — context cleared, next iteration starts fresh

## PRD / Task List Structure

Two prevalent formats. The snarktank/ralph format uses JSON; Huntley's original uses markdown. Both work. The key properties are the same: each task has an ID, description, acceptance criteria, priority order, and a pass/fail flag.

### JSON format (snarktank/ralph)

```json
{
  "project": "MyApp",
  "branchName": "ralph/feature-name",
  "description": "Feature description",
  "userStories": [
    {
      "id": "US-001",
      "title": "Add status field to database",
      "description": "As a developer, I need to store task status.",
      "acceptanceCriteria": [
        "Add status column: 'pending' | 'in_progress' | 'done' (default 'pending')",
        "Migration runs successfully",
        "Typecheck passes"
      ],
      "priority": 1,
      "passes": false,
      "notes": ""
    }
  ]
}
```

### Markdown format (Huntley original)

`IMPLEMENTATION_PLAN.md` — a bullet-point list sorted by priority. No fixed schema; let the LLM manage the format. Tasks are marked complete/incomplete inline. The plan is disposable: regenerate it whenever it drifts.

## Task Sizing Rules

Each task must be completable in ONE iteration (one context window).

**Right-sized:**
- Add a database column and migration
- Add a UI component to an existing page
- Update a server action with new logic
- Add a filter dropdown to a list

**Too big (split these):**
- "Build the entire dashboard" → schema, queries, components, filters
- "Add authentication" → schema, middleware, login UI, session handling
- "Refactor the API" → one story per endpoint

**Rule of thumb:** If you cannot describe the change in 2-3 sentences, it's too big.

---

## Task Ordering

Dependencies first. Earlier tasks must not depend on later ones.

1. Schema / database changes (migrations)
2. Server actions / backend logic
3. UI components that consume the backend
4. Dashboard / summary views that aggregate

---

## Acceptance Criteria

Must be verifiable — something the agent can CHECK.

**Good:** "Add `status` column with default 'pending'" / "Filter dropdown has options: All, Active, Done" / "Typecheck passes"

**Bad:** "Works correctly" / "Good UX" / "Handles edge cases"

Always include "Typecheck passes" on every story. For UI stories, include browser verification.

## Agent Prompt (Building Mode)

The prompt given to each fresh agent instance. This is the snarktank/ralph CLAUDE.md variant:

```markdown
# Ralph Agent Instructions

You are an autonomous coding agent working on a software project.

## Your Task

1. Read the PRD at `prd.json`
2. Read the progress log at `progress.txt` (check Codebase Patterns section first)
3. Check you're on the correct branch from PRD `branchName`
4. Pick the highest priority user story where `passes: false`
5. Implement that single user story
6. Run quality checks (typecheck, lint, test)
7. Update CLAUDE.md / AGENTS.md if you discover reusable patterns
8. If checks pass, commit ALL changes: `feat: [Story ID] - [Story Title]`
9. Update the PRD to set `passes: true` for the completed story
10. Append your progress to `progress.txt`

## Progress Report Format

APPEND to progress.txt (never replace):

    ## [Date/Time] - [Story ID]
    - What was implemented
    - Files changed
    - **Learnings for future iterations:**
      - Patterns discovered
      - Gotchas encountered
      - Useful context
    ---

## Consolidate Patterns

If you discover a reusable pattern, add it to `## Codebase Patterns` at the
TOP of progress.txt. Only general/reusable patterns, not story-specific details.

## Quality Requirements

- ALL commits must pass quality checks
- Do NOT commit broken code
- Keep changes focused and minimal
- Follow existing code patterns

## Stop Condition

If ALL stories have `passes: true`, reply with:
<promise>COMPLETE</promise>

Otherwise end normally (next iteration picks up next story).

## Important

- Work on ONE story per iteration
- Commit frequently
- Keep CI green
- Read Codebase Patterns before starting
```

## Agent Prompt (Planning Mode — Huntley)

```
0a. Study `specs/*` with up to 250 parallel subagents.
0b. Study IMPLEMENTATION_PLAN.md (if present).
0c. Study `src/lib/*` with up to 250 parallel subagents.
0d. For reference, source is in `src/*`.

1. Study IMPLEMENTATION_PLAN.md and use up to 500 subagents to study `src/*`
   and compare against `specs/*`. Analyze findings, prioritize tasks, and
   create/update IMPLEMENTATION_PLAN.md as a bullet point list sorted by
   priority. Consider TODOs, placeholders, skipped tests, inconsistent patterns.

IMPORTANT: Plan only. Do NOT implement. Do NOT assume missing; confirm with
code search first.
```

## Agent Prompt (Building Mode — Huntley)

```
0a. Study `specs/*` with up to 500 parallel subagents.
0b. Study IMPLEMENTATION_PLAN.md.
0c. For reference, source is in `src/*`.

1. Implement per specs using parallel subagents. Follow IMPLEMENTATION_PLAN.md,
   choose the most important item. Before changes, search codebase (don't assume
   not implemented). Up to 500 subagents for searches, only 1 for build/tests.
2. After implementing, run tests. If functionality is missing, add it per specs.
3. When you discover issues, immediately update IMPLEMENTATION_PLAN.md.
4. When tests pass, update IMPLEMENTATION_PLAN.md, git add -A, git commit, git push.

99999. Capture the why in documentation.
999999. Single sources of truth, no migrations/adapters.
9999999. Create git tags for successful builds.
999999999. Keep IMPLEMENTATION_PLAN.md current — future work depends on this.
9999999999. Update AGENTS.md with operational learnings, keep brief.
99999999999. Resolve or document any bugs you notice.
999999999999. Implement completely. No placeholders or stubs.
9999999999999. Periodically clean completed items from IMPLEMENTATION_PLAN.md.
```

## Outer Loop Script (minimal)

```bash
#!/bin/bash
# Usage: ./ralph.sh [--tool amp|claude] [max_iterations]
set -e

TOOL="claude"
MAX_ITERATIONS=10

# ... argument parsing ...

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
PRD_FILE="$SCRIPT_DIR/prd.json"

for i in $(seq 1 $MAX_ITERATIONS); do
  echo "=== Ralph Iteration $i of $MAX_ITERATIONS ==="

  OUTPUT=$(claude --dangerously-skip-permissions --print < "$SCRIPT_DIR/CLAUDE.md" 2>&1 | tee /dev/stderr) || true

  if echo "$OUTPUT" | grep -q "<promise>COMPLETE</promise>"; then
    echo "Ralph completed all tasks!"
    exit 0
  fi

  sleep 2
done

echo "Reached max iterations without completing."
exit 1
```

## Outer Loop Script (enhanced — with plan/build modes)

```bash
#!/bin/bash
# Usage: ./loop.sh [plan|plan-work "desc"] [max_iterations]

set -euo pipefail

if [ "${1:-}" = "plan" ]; then
    MODE="plan"; PROMPT_FILE="PROMPT_plan.md"; MAX_ITERATIONS=${2:-0}
elif [ "${1:-}" = "plan-work" ]; then
    MODE="plan-work"; WORK_DESCRIPTION="$2"; PROMPT_FILE="PROMPT_plan_work.md"
    MAX_ITERATIONS=${3:-5}; export WORK_SCOPE="$WORK_DESCRIPTION"
elif [[ "${1:-}" =~ ^[0-9]+$ ]]; then
    MODE="build"; PROMPT_FILE="PROMPT_build.md"; MAX_ITERATIONS=$1
else
    MODE="build"; PROMPT_FILE="PROMPT_build.md"; MAX_ITERATIONS=0
fi

ITERATION=0
CURRENT_BRANCH=$(git branch --show-current)

while true; do
    [ $MAX_ITERATIONS -gt 0 ] && [ $ITERATION -ge $MAX_ITERATIONS ] && break

    if [ "$MODE" = "plan-work" ]; then
        envsubst < "$PROMPT_FILE" | claude -p \
            --dangerously-skip-permissions --model opus --verbose
    else
        cat "$PROMPT_FILE" | claude -p \
            --dangerously-skip-permissions --model opus --verbose
    fi

    git push origin "$CURRENT_BRANCH" 2>/dev/null || \
        git push -u origin "$CURRENT_BRANCH"

    ITERATION=$((ITERATION + 1))
    echo "======================== LOOP $ITERATION ========================"
done
```

## Key Principles

### Context is precious
- 200K advertised → ~176K usable
- 40-60% utilization is the "smart zone"
- Tight tasks + 1 task per loop = max context efficiency
- Verbose inputs degrade determinism

### Deterministic setup
- Every iteration seeds with the same files
- Agent starts from known state each time
- Scoping happens at plan creation, not runtime

### Backpressure is critical
- Tests, typecheck, lint = the gradient toward "works"
- Agent cannot commit broken code
- "If functionality is missing, it's your job to add it"

### Plan is disposable
- Wrong? Delete it and regenerate
- Cost of regeneration = one planning loop
- Cheaper than Ralph going in circles

### Don't assume not implemented
- Always search codebase before adding new code
- "This nondeterminism is the Achilles' heel of Ralph"
- Failure to check → duplicate implementations

### One task per loop
- Monolithic: single process, single repo, single task
- No multi-agent coordination needed
- Context cleared between iterations

### Add signs when Ralph fails
- Start with no guardrails
- When Ralph fails a specific way, add a prompt guardrail
- Prompts evolve through observed failure patterns
- "Tune it like a guitar"

### Sandbox everything
- `--dangerously-skip-permissions` bypasses all safety
- "It's not if it gets popped, it's when"
- Docker containers, Fly Sprites, E2B for isolation
- Only expose the API keys and deploy keys needed for the task
