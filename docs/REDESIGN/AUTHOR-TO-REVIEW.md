## Waiting on you

1. **The lines for a machine of your own.** `shrimpy invite` with no name, and `shrimpy join <link>` on the other machine, are built as you saw them on 2026-10-07, and [the network](design/6-network.md) has what each prints. You agreed to the way in as long as it was simple and clean, and haven't said yes or no to these lines: they are yours to change. Once the gateway has its key, the link also carries the key's fingerprint, so it gets longer.
2. **An agent hearing a thread while it works in it.** Your idea of 2026-10-06: what anyone says in a thread reaches an agent that is working there at its next step, and wakes nobody. Pi has the piece for it, a submission that adds to a session and never starts a turn. [The proposal](proposals/hearing-a-thread.md) has how it would work, ten details with what I'd do about each, what it costs, and the version with no mechanism, which is one sentence in the instructions.
3. **`shrimpy up` starts an agent that ends again, alone.** On 2026-10-04 you confirmed that `up` stops everything it started when any one program ends, an agent included. You asked on 2026-10-07 that adding an agent take nobody starting anything, and I built more than that with it: with no agents named, `up` now starts an agent that ends again by itself, after a pause that grows while it keeps failing, and stops everything only when the gateway or the chat server ends. I said so before it was built, and you haven't said yes or no to that part. [The row](design/1-programs.md) has what it does.
4. **`shrimpy login` offers Anthropic's subscription sign-in.** It lists "Anthropic (Claude Pro/Max)" first among its subscriptions, as pi-ai offers it. An agent signed in that way is presented to Anthropic as Claude Code, in its system prompt and its requests, and nothing tells you. Anthropic's legal page for Claude Code says third-party developers may not offer Claude.ai login or route requests through a subscriber's credentials, and its Acceptable Use Policy, which names services that disguise the calling client, takes effect on 2026-11-12. Reports of 2026-11-09 and 2026-11-10 on Pi's tracker have Anthropic's API refusing pi-ai 1.0.0's Claude Code version for `claude-fable-5-2`. The six other subscriptions it offers, your OpenAI one among them, weren't checked against their vendors' terms. pi-ai 1.5.2 also offers Earendil's own hosted gateway, Radius, with a sign-in of its own, which `shrimpy login` would list the same way. [The coding-agents note](../research/coding-agents-scout-2026-11-11.md#for-the-owner) has the details and the smallest fix: leave this sign-in out of `shrimpy login`, refuse `sk-ant-oat` keys, and point subscribers to an API key. Take it out before the release, or keep it with a current pi-ai and a warning?
