# 🦐 TUI-001: Shrimpy TUI Slash Commands and Settings Coherence

Status: todo
Priority: P2
Area: TUI

## Why
Shrimpy currently leans on Pi's TUI, but the default `/` slash commands and settings experience should feel like one coherent Shrimpy surface. Users should be able to discover and use Shrimpy-native actions from the TUI without remembering which parts come from Pi and which parts are layered by Shrimpy.

## Build
- Audit the default Pi TUI slash commands exposed through Shrimpy.
- Decide which Pi slash commands should remain unchanged, be relabeled, be hidden, or be wrapped with Shrimpy-aware behavior.
- Add Shrimpy-specific slash commands for common workspace, channel, agent, context, skill, model, and diagnostic workflows.
- Make slash command help text explain the Shrimpy behavior and vocabulary first.
- Make TUI settings feel merged between Pi and Shrimpy instead of split across unrelated concepts.
- Route new behavior through normal Shrimpy CLI/service boundaries where possible, so slash commands remain another agent-friendly surface rather than a separate control plane.

## Slices
- TUI-001A: Additive Shrimpy slash commands through Pi's existing `pi.registerCommand()` extension API. This includes command discovery and read-only workspace, agent, channel, context, skill, model, and diagnostic panels. It should not patch or fork Pi. **Done on the memory-redesign branch.**
- TUI-001B: Pi-owned built-in command/settings ownership. This includes hiding, filtering, relabeling, or wrapping built-in slash commands; merging `/settings`; changing built-in autocomplete/help text; and visually hiding `!` / `!!` bash affordances. This is the remaining work and may need [PI-001](pi-001.md) if existing extension APIs cannot express it.

## Progress
- TUI-001A is implemented for final review as a bundled extension. It registers `/workspace`, `/agents`, `/channels`, `/context`, `/skills`, `/models`, `/doctor`, and expanded `/shrimpy` help without patching Pi.
- Remaining work is TUI-001B: make Pi-owned built-ins, settings, and command vocabulary feel like one Shrimpy surface.

## Candidate Commands
- `/workspace` for current workspace paths, config, and turn-context files.
- `/agent` or `/agents` for active agent identity, agent context, and available agents.
- `/channels` for channel status and recent activity pointers.
- `/context` for agent context files and context-source inspection hooks.
- `/skills` for available workspace and agent skills.
- `/models` for provider/model state and active model selection.
- `/doctor` for diagnostics and repair guidance.
- `/shrimp` or `/shrimpy` for Shrimpy-specific help and command discovery.

## Settings Ideas
- Present Pi runtime settings and Shrimpy workspace settings in one settings view.
- Clearly distinguish volatile session settings from persisted workspace config.
- Show where each setting comes from when useful: Pi runtime, Shrimpy config, agent config, or session override.
- Prefer editing through Shrimpy commands/config helpers instead of direct ad hoc file mutation.
- Keep settings output readable by humans while preserving structured command paths for agents.

## Current Audit
Shrimpy currently launches Pi's stock `InteractiveMode` directly and does not pass a custom built-in slash command registry. Pi owns the built-in slash command list, command dispatch, autocomplete, selectors, settings UI, and hidden debug/easter-egg commands. Shrimpy affects the surface through a custom resource loader, a seeded in-memory Pi `SettingsManager`, and bundled extensions.

### Built-In Pi Commands Exposed
- `/settings` opens Pi's settings selector.
- `/model [provider/model]` selects the active model.
- `/scoped-models` enables/disables models for Ctrl+P cycling.
- `/export [path]` exports the session as HTML or JSONL.
- `/import <path>` imports and resumes a JSONL session.
- `/share` shares the session as a secret GitHub gist.
- `/copy` copies the last agent message to clipboard.
- `/name [name]` sets the Pi session display name.
- `/session` shows Pi session info and stats.
- `/changelog` shows Pi changelog entries.
- `/hotkeys` shows keyboard shortcuts.
- `/fork` creates a new fork from a prior message.
- `/clone` duplicates the current active branch into a new session.
- `/tree` navigates the Pi session tree.
- `/login` starts provider OAuth login.
- `/logout` starts provider OAuth logout.
- `/new` starts a new Pi session.
- `/compact [instructions]` manually compacts session context.
- `/resume` resumes another Pi session.
- `/reload` reloads keybindings, extensions, skills, prompts, and themes.
- `/quit` exits Pi interactive mode.

Pi also handles hidden `/debug` and `/arminsayshi` commands in submit handling, but does not list them in built-in autocomplete.

### Shrimpy Extension Commands Exposed
- `/shrimpy` shows Shrimpy version info.
- `/thinking <off|minimal|low|medium|high|xhigh|on>` sets the session thinking level.
- `/toolrows` toggles compact tool rendering between one-line and expanded detail.

### Other Slash-Like Inputs
- Prompt templates may appear as slash commands if Pi prompt template discovery is enabled. Shrimpy passes `noPromptTemplates` through runtime config.
- Skill slash commands are effectively disabled today because Shrimpy's resource loader sets `noSkills: true` and `additionalSkillPaths: []`, even though Shrimpy separately advertises skills in its own assembled prompt context.
- Extension commands are included in the same autocomplete list unless they conflict with a Pi built-in command. Built-in command names win.
- `!` and `!!` bash commands are not slash commands, but they share the primary TUI command surface and remain Pi-owned behavior.

### Settings Exposed Today
Pi's `/settings` currently covers auto-compaction, image display/resizing/blocking, skill command enablement, steering/follow-up delivery mode, provider transport, HTTP idle timeout, thinking level, theme, thinking block visibility, changelog collapse, update/install telemetry, warnings, double-escape behavior, tree filter mode, hardware cursor, editor padding, autocomplete height, quiet startup, and clear-on-shrink behavior.

In Shrimpy these settings are backed by `createInlineSettingsManager`, seeded from Shrimpy runtime config. That means the TUI feels like Pi settings, while persistence and ownership are unclear: some options affect the live Pi session, some mutate the in-memory settings manager, and they do not obviously map back to `workspace/config/shrimpy.json`.

### Product Gaps
- Additive Shrimpy commands now cover workspace, agents, channels, context, skills, models, and doctor. Surfaces, schedules, and gateway state still need either commands or clear inspection paths.
- `/settings` is not Shrimpy-aware and does not distinguish Pi runtime state, Shrimpy runtime config, agent config, session override, or workspace config.
- `/session`, `/new`, `/resume`, `/fork`, and `/tree` use Pi session vocabulary, not Shrimpy's agent/channel/session vocabulary.
- `/login`, `/logout`, `/model`, and `/scoped-models` operate on Pi auth/model registry paths, which Shrimpy relocates under workspace state; the UI text does not make that ownership clear.
- Current Pi `/login` includes a provider selector and headless device-code options for Codex subscriptions. Shrimpy does not need to rebuild that flow, but it should make clear that stored auth lives in workspace `state/pi/auth.json` when launched through Shrimpy.
- `/reload` says it reloads skills/prompts/themes/extensions, but Shrimpy intentionally suppresses cwd-discovered AGENTS files, append prompts, and Pi skills. The command text can imply more reloadable surface than Shrimpy allows.
- `/changelog` is Pi's changelog, not Shrimpy's project/runtime changelog.
- `/shrimpy` exists but is too thin to serve as Shrimpy command discovery.

### Implementation Hooks Found
- Shrimpy enters the TUI in `runInteractiveAgentSession` by constructing `new InteractiveMode(runtime, { initialMessage })`.
- Shrimpy wraps prompt preparation so normal prompts receive turn briefings while raw slash commands remain available for Pi interception.
- Pi command names live in `BUILTIN_SLASH_COMMANDS`; Pi builds autocomplete from those, prompt templates, extension commands, and skill commands.
- Pi handles built-in command dispatch inside `InteractiveMode.setupEditorSubmitHandler`.
- Pi exposes extension commands through `pi.registerCommand`, which Shrimpy already uses for `/shrimpy`, `/thinking`, and `/toolrows`.
- Pi exposes command inspection through `pi.getCommands()`. That can support Shrimpy-owned help or diagnostics even though it does not let Shrimpy replace built-in command dispatch.
- Pi exposes tool inspection/mutation, built-in tool selection, `excludeTools`, same-name tool overrides, and `user_bash` interception. Core capability enforcement should live in [TOOLS-001](tools-001.md), not in a TUI fork.
- Pi extension input events now include `streamingBehavior`, so Shrimpy input handlers can distinguish idle prompts from mid-stream steers and queued follow-ups if needed.
- Pi settings selector values and callbacks are hardwired in `InteractiveMode.showSettingsSelector`, so a truly merged settings view likely needs either an upstream-style extension point or a Shrimpy-owned interactive surface.

## Boundaries
- Do not fork the Pi TUI wholesale unless a specific Pi extension point is missing.
- Do not create a parallel settings system for Shrimpy.
- Do not add legacy aliases or compatibility shims for old command names unless explicitly needed.
- Do not hardwire agent policy into slash commands; commands should inspect, route, configure, or launch normal workflows.
