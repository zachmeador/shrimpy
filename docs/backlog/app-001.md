# 🦐 APP-001: App and Config Pattern Examples

Status: todo
Priority: P2
Area: Apps

## Why
Shrimpy needs a living examples document for app/config ideas that emerge from real user workspaces. The goal is to make the path from simple personal automation to richer app-agent habitats concrete, without turning the examples into generic low-signal templates.

These examples should later feed setup skills, guided init flows, and scheduled check-ins where Shrimpy consults with the user about deeper ways they could use the system.

## Build
- Create a Markdown examples document that moves from simple to complex Shrimpy app/config patterns.
- Ground examples in real workspace shapes: recurring tasks, channels, skills, prompts, schedules, files, resident agents, and useful state.
- Include enough structure that the examples can become skill resources for init or advisory sessions.
- Include an opt-in "out there" examples bundle for playful/experimental configs, separate from the practical starter path.
- Connect the examples to onboarding/admin flows rather than baking them into runtime policy.

## Boundaries
- Do not implement the init skill, scheduled check-in loop, or app-agent behavior as part of this item.
- Do not make examples artificially generic; favor patterns that reflect serious user workspaces and durable habits.
- Do not let playful examples crowd the default setup path; they should be available as inspiration after the user has a working mechanic and main agent.
- Do not create a second app/config control plane. Examples should describe normal workspace files and Shrimpy concepts.
